## Interfaces

Root implementation ruling: `validate_runtime_config(raw:dict[str,object])->RuntimeConfig` uses a frozen dataclass with password excluded from repr. Exactly9keys are allowed: operation_id canonical UUID, host literal127.0.0.1, strict integer port5455 (not bool), database mobility_catalog_acceptance, user mobility_catalog_reader, nonempty password, container nckh-mobility-acceptance-db, project nckh-mobility-acceptance, volume nckh_mobility_acceptance_pgdata. Missing/extra/wrong fields raise only `ValueError("Invalid acceptance configuration.")` with no input echo. `connect_readonly(config:RuntimeConfig|dict,*,engine_factory=create_engine)->Engine` revalidates even dataclass inputs before factory/connection, uses SQLAlchemy URL.create with postgresql+psycopg, connect_timeout2, postgresql_readonly=True and REPEATABLE READ. Returns engine; verify owns connection and DB/user/readonly/DML checks. Injectable factory is a harness-only test seam proving wrong target never reaches engine creation. CLI failure is one stdout JSON line `{"status":"FAIL","code":"ACCEPTANCE_NOT_VERIFIED"}`, exit1, no traceback/secret/raw exception. Cost if incorrect: acceptance cannot proceed, not a fallback to another DB.

Pure helper seams: `canonical_records_sha256(records:list[str])->str` sorts UTF-8 row bytes and hashes each `ASCII(byte_length)+b":"+row_bytes+b"\n"`; reject non-string records. `canonical_json_sha256(value)->str` hashes UTF-8 JSON with sorted keys, compact separators, ensure_ascii=False and allow_nan=False. `validate_catalog_projection(source_rows:list[dict],actual_rows:list[dict])->dict` compares independently source-derived approved DTO fields/order/original IDs against fixed spec counts, not caller-supplied expected counts or the production reader's converter. Failure is generic `ValueError("Catalog acceptance mismatch.")`. `validate_real_receipt_document(receipt:dict,expected_source_rows:list[dict],expected_code_pin_hashes:dict[str,str],expected_operation:dict)->None` checks pure receipt schema/AC/exact pins/operation/source-ID/DTO/digest/evidence contracts; its I/O wrapper recomputes every specified file hash and derives expected_operation from validated private config, never from the receipt. Synthetic789 fixtures/receipt objects may exercise unit guards only and never generate a real acceptance artifact. Internal helper naming remains the worker's responsibility, not an architecture change.

Root coverage ruling: derive the independent expected public object-name set from SOURCE_BASELINE.json inside the SHA-pinned Docker ZIP, or a stage copy only after matching the archived member hash. Its18table names plus catalog_handoff_metadata are the clone's19public ordinary tables; catalog_handoff_v1 is the separate view digest. Require exactly this19key set in both before/after digests. Do not reuse original production counts/digests as clone expectations. Receipt verification must reject removing the same table from both digests even when equality remains true. The pure unit seam may carry the trusted name set in expected_operation; the real wrapper derives it from the archive, not the receipt or caller assertion. Cost if incorrect: a real extra/missing schema object fails acceptance and needs root review, not silent partial data protection.

Harness Python CLI: `python scripts/mobility_catalog_acceptance.py verify --runtime-dir <private-dir>`; it reads a reviewed private JSON connection config (operation_id, host127.0.0.1, port5455, database mobility_catalog_acceptance, user mobility_catalog_reader, reader password, container/project/volume names), validates exact target and role before any engine connection, computes comparisons, starts only owned test API/UI processes with no crawler and invokes the browser helper. No secret arguments/output. Fail closed/nonzero on missing config/DB/browser/comparison. After actual success write REAL_ACCEPTANCE.json exactly as specified; `verify-receipt --runtime-dir <private-dir>` validates all source/runtime/evidence pins and AC values without treating an offline/mock result as real success.

Browser helper: `node apps/web/e2e/mobility-catalog-acceptance.cjs <expected-public-data-file> <redacted-browser-receipt-file> <screenshot-file>`; expected data is derived directly from sealed789 by Python, includes operation_id and canonical source-derived public data, kept private and never printed. Uses installed Playwright Chromium library for this explicit acceptance-test task; only loopback3032 allowed, no route interception replacing catalog. All actual789DOM IDs must equal expected IDs. For each listing assert visible original title and correct NULL-area/value label; select all partial/withheld representatives and both no-coordinate rows, asserting description text/labels and contact href against the oracle, no-coordinate rows selectable without pin and route buttons disabled. Preserve actual sanitized description text, do not print it. Validate at least one positioned row returning NOT_CONFIGURED/nullable route and nearby and both missing-position cases returning LOCATION_UNAVAILABLE via real HTTP; never synthetic route results. Writes aggregate receipt/screenshot only. Python verifies helper exit and all Boolean checks, operation/expected hash before success.
